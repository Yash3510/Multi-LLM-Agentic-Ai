## Summary

Each agent could be pinned to its own model, a test suite appeared, a turn got
upper bounds on image size and reply length, and greetings stopped going
through the chain.

## Why it changed

- A full-page scan sent untouched, with no cap on the reply, made one turn run
  for over twenty minutes on a 6 GB GPU (`5223fdb`).
- The root cause was found the same day: a 65k context window pushed the vision
  model's KV cache out of VRAM, so inference fell back to CPU (`3bdee64`).
- "hello" ran the full chain and asked for approval of a greeting (`abbcab7`).

## Technical changes

- **Per-agent model valves** (`285c8ce`). `friday_model`, `jarvis_model` and
  `ultron_model`. Blank followed the routed model; this default was changed
  later ([ADR-0003](../decisions/0003-verify-on-a-different-model.md)).
- **Tool test suite** (`285c8ce`). 19/19 at the time: the sandbox executes,
  blocks the network, is read-only and enforces the wall clock; the
  deliverable is valid OOXML and refuses empty or unattributed requests; the
  audit classifies addresses correctly.
- **Synthetic demo documents** (`285c8ce`). SOP-MEC-014 and a P-101B inspection
  report, generated by a script.
- **Bounds** (`5223fdb`). `vision_max_edge` downscales images; `max_tokens`
  caps every agent reply. A 760 px image with a 200-token cap answered the same
  document correctly in 19 s.
- **Verification record** (`3bdee64`). Local RAG verified end to end in about
  0.3 s. Vision was marked unproven, with the cause.
- **Conversational fast path** (`abbcab7`). A strict matcher for purely social
  messages. They are answered on the small model with no agents and no
  approval. Measured at about 4-10 s.

## Impact

The chain became usable on the target hardware, and the approval gate stopped
being trained into a reflex.
See [ADR-0005](../decisions/0005-load-models-at-8192-context.md) and
[ADR-0008](../decisions/0008-answer-conversation-directly.md).

# Phase 0 foundations

## What changed

Phase 0 continued from the frontend decisions of [2026-10-08](2026-10-08-4ce-core.md), in small commits on `4ce-core`, pushed to GitHub as they were made:

- **Repository (WP-F-01, F-12, F-16):** root files, the uv workspace on Python 3.12, the `justfile`, `AGENTS.md` from master plan Appendix E, `CONTRIBUTING.md` with the agent least-privilege notes, and the repo check with its scaffolds (`just new-package`, `just new-pack`, `just new-doc`).
- **Checks:** the neutrality check (F-04), import-linter contracts (F-03), the docs check (F-15), the SBOM, licence gate, import scan and third-party bundle check (F-02), gitleaks and the commit-message hook through pre-commit, all inside `just check`.
- **CI (F-01):** `just setup` and `just check` on Linux, Windows and macOS; pull requests also get the commit, title, work-log, drift and ADR rules. Pull request and issue templates, Dependabot.
- **`core/common` (F-05):** typed settings from `FOURCE_*` variables, secrets hidden.
- **Bundled services (F-10):** PostgreSQL, Redis, MinIO, Prometheus and Grafana in a hardened Compose stack, with each one's licence, notices, version and source in `deploy/third-party/`.
- **`core/packs` (PK-01):** draft JSON Schemas for the pack manifest and the Rule Pack spec v1.
- **Knowledge base (F-14):** the index and tag list, state, glossary, templates, folder indexes, the architecture pages (overview, repository, documentation, licences, services), a research note on MinIO, the shared Obsidian settings, and seven proposed ADRs.
- **After a fresh-eyes review:** eight important fixes to the checks themselves (indentation-only commits accepted; the repo check reads only git's index; accepted ADRs can only become superseded; the bundle check covers every service, both compose extensions and built commits; `just sync` added; drift checks real paths, survives renames and skips ADRs; Conventional titles for Dependabot; PR rules re-run on title and label changes), plus most of the minor ones: fail-closed licence checks, revert subjects, migration names, TODOs in more files, real signature timestamps, LF line endings from the scaffold on Windows, isolated tests, and exact pins for just, pre-commit and gitleaks.

## Why

Phase 0 sets the rules every later change is checked against, so they have to exist, and be enforced, before the first line of product code. Each check was shown to fail on a planted problem before it was trusted.

## How it was verified

All on 2026-10-12, on the Debian laptop, Python 3.12.15, uv 0.13.0, Docker 26.1.5:

- **A fresh clone passes the Phase 0 exit check on Linux:** `git clone --branch 4ce-core`, then `just setup` (exit 0; hooks installed in the clone), then `just check` (exit 0): ruff and pyright clean, 3 import contracts kept, repo, neutrality and docs checks clean, 30 SBOM components licence-checked and 6 Python files import-scanned, 5 bundled services complete, gitleaks found no leaks (74 commits scanned at that head), 94 tests passed.
- **Each check was broken on purpose and failed:** a settings field made a plain string, the root allowlist disabled, the neutrality matcher's left boundary removed, inline-code link skipping removed, GPL let through the gate, the `fource` import skip removed, a missing-reading `PASS` allowed in the rule-pack schema. Each made its tests fail, and the code was restored.
- **On the real tree:** a planted AWS key was caught by the gitleaks hook (2 findings); `Added stuff` was rejected by the commit-message hook; an import of a non-public module and a `common` → other-package import both broke the import contracts; an unstaged orphan page failed the docs check; a scaffolded pack with `risk_tier: 7` failed the repo check; without `licence-review.toml`, exactly grimp, import-linter and nodeenv failed the gate.
- **The services:** `just dev` built MinIO from source and reported all five containers healthy; the checks run against them are on the [services page](../../../architecture/services.md#measured); `just down` stopped them.
- **CI on GitHub:** `actionlint` 1.7.12 found no problems in `ci.yml`. The first runs passed on Linux and macOS and stopped on Windows at the licence gate: `colorama`, installed only on Windows, says just "BSD License". Its LICENSE.txt at 0.4.6 was read (BSD-3-Clause) and recorded, and from commit `2506b19` (run 38240500331) `just setup` and `just check` pass on all three systems.
- **The review fixes:** each came with a test that failed first, including tests against real temporary repositories for the commit checks, `just sync` and the docs check's PR rules. 116 tests pass.

## Decisions

Proposed: [ADR-0009](../../../adr/0009-own-core-and-clean-room.md), [ADR-0015](../../../adr/0015-licence-allowlist-and-sbom-gate.md), [ADR-0018](../../../adr/0018-sector-neutral-core.md), [ADR-0023](../../../adr/0023-third-party-services.md), [ADR-0029](../../../adr/0029-repository-layout-and-working-rules.md), [ADR-0031](../../../adr/0031-documentation-knowledge-base.md), [ADR-0032](../../../adr/0032-agent-instructions.md). Followed, still proposed: ADR-0035 and ADR-0036.

Made with the project lead during the work:

- **The frontend is on hold on `4ce-core`.** Pranay, the frontend owner, develops `apps/web` (following ADR-0035 and ADR-0036, both still proposed); this stream builds the backend and the database first, and the server's OpenAPI document is the contract between the two. Node 24 is installed when `apps/web` lands here.
- Dependabot PRs get their work-log entry from the person who reviews them.
- MinIO is built from its last release for development; a fork comparison is in [MinIO patch source](../../../research/minio-patch-source.md).
- 4CE stays in [Yash3510/Multi-LLM-Agentic-Ai](https://github.com/Yash3510/Multi-LLM-Agentic-Ai) instead of a new repository, and `4ce-core` is its trunk: CI runs on pushes to it, Dependabot targets it, and `AGENTS.md`, CONTRIBUTING and the docs name it where the plan says `main` ([ADR-0009](../../../adr/0009-own-core-and-clean-room.md)).

Small departures from the master plan's text, each needed by another rule of the plan:

- `.env.example` sits at the root (the plan says it is committed, but its root list omits it).
- `.obsidian/templates.json` is shared, because it is what points Templates at `docs/templates/`.
- The scaffold templates live in `tools/scaffold.py`, not a `tools/scaffold/` folder.
- The licence gate reads licences from the CycloneDX SBOM; license-checker isn't needed for Python.
- A new pack starts at risk tier 3.

## Known limits and follow-ups

Issues aren't open yet (the GitHub project isn't set up); each item becomes one.

- **The Phase 0 exit isn't fully met:** there is no app with a login yet. The backend comes next (`apps/server`, WP-F-06, WP-ID-01); the screens come with Pranay's frontend.
- **Human-only items:** CODEOWNERS needs a GitHub handle for each of R1 to R4; branch protection, signed commits, labels, milestones and the project board are GitHub settings; the trademark search; accepting the proposed ADRs; ADR-0025 (MinIO's patch source).
- **The repository on GitHub:** `4ce-core` should become the default branch, since Dependabot and the issue and pull request templates are read from the default branch. `just setup` installs git hooks that every branch of a clone shares; they are installed with `--allow-missing-config`, so the fork's branches are unaffected.
- **Legal review (ADR-0023):** Grafana's image reports a build commit that isn't in its public repository.
- **Not yet built:** the npm side of the licence gate, `release.yml` and `nightly-evals.yml`, and Git LFS on this machine.
- **Review follow-ups left open:** Obsidian saved views (WP-F-14); listing new dependencies in each PR automatically (§2.5); the bundled services as SBOM entries (§2.7); the verified-author-email rule (a GitHub setting); `pids_limit`, memory limits and file-based secrets in Compose; checking that LFS-pattern files are LFS pointers; the Svelte and TypeScript naming rules (with `apps/web`); an SBOM taken from `uv.lock` for every system instead of the running environment; and the plan's term `claim`, which will collide with OIDC "claims" in `core/identity`.
